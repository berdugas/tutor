Why This ArchitectureThe core problem: any API key placed inside a browser HTML file is fully visible to anyone who opens DevTools. This is a real security risk — the key could be stolen and used to run up charges on the Kimi account.The solution is a two-layer deployment:LayerRolePlatformCostFront-end appWhat the user sees and interacts withVercel (static hosting)FreeAPI proxyHolds the Kimi key, forwards requestsCloudflare WorkersFreeAI backendProcesses images, generates contentKimi K2.5 API (Moonshot AI)Per tokenThe user's browser (Chrome on Android) never communicates directly with Kimi. Every request goes through the Worker. The Kimi API key is stored as an encrypted environment variable on Cloudflare — it is never in the HTML file and never visible in the browser.Request flowUser's phone (Chrome)    │    │  POST /api/analyze    │  { image: base64, prompt: '...' }    │  Header: X-AralMate-Secret: <shared_secret>    ↓Cloudflare Worker  (worker.js)    │  Validates X-AralMate-Secret header    │  Attaches Authorization: Bearer <KIMI_API_KEY>    │  Forwards to Kimi API    ↓Kimi K2.5 API  (api.moonshot.cn)    │  Processes image + prompt    │  Returns JSON lesson/quiz/flashcards    ↓Cloudflare Worker    │  Returns response to app    ↓User's phone — Alon displays the result⚠  IMPORTANTThe X-AralMate-Secret is a shared secret between the Worker and the HTML app.It is NOT the Kimi API key. Cloudflare WorkerThe Worker is a small piece of server-side JavaScript that runs on Cloudflare's global network. It does exactly three things: validates the secret header, attaches the Kimi API key, and proxies the request.3.1  Worker code (worker.js)Create a new file called worker.js with the following content:// AralMate Cloudflare Worker — Kimi API Proxy// Deploy this to Cloudflare Workers.// Set KIMI_API_KEY and ARALMATE_SECRET as encrypted env variables.export default {  async fetch(request, env) {    // 1. Handle CORS preflight    if (request.method === "OPTIONS") {      return corsResponse(null, 204);    }    // 2. Only allow POST    if (request.method !== "POST") {      return corsResponse(JSON.stringify({ error: "Method not allowed" }), 405);    }    // 3.
